# Architecture

Lottie Editor is a client-only single-page app (Vite + React + TypeScript). Everything runs in
the browser; files never leave the device.

```
src/
  app/          App shell: router, top bar, status bar, menus, core commands, dialog host,
                the editor workspace (lazy chunk)
  commands/     Command registry, keyboard shortcuts (+ per-page scope), dialog/paste/file registries
  components/ui Design-system primitives (buttons, fields, menus, dialogs, …)
  components/lottie  Shared layer/shape icons and node labels
  export/       Offscreen rendering and encoders (GIF, MP4/WebM, PNG, dotLottie, TGS, embed code)
  features/     One folder per feature (io, viewport, timeline, layers, inspector, colors, code,
                assets, docops, insights, export, workspace, themes, home, customize, optimizer)
  i18n/         Typed dictionaries (en, ru), one file per namespace
  lib/          Generic helpers (colors, math, locale-aware formatting, downloads, events)
  lottie/       Pure domain logic for the Lottie format (no React, no DOM, unit-tested):
                evaluation, keyframes, layers, colors, timing, bounds, validation, stats,
                effects, slots and themes, SVG import (svg/), element replacement, the
                optimizer engine (optimizer/)
  player/       lottie-web wrapper (render copy preparation, double-buffered player, font probes)
  samples/      Built-in sample animations (generated by scripts/samples)
  store/        Global state (document + history, playback, preferences, transient UI)
```

## Services and routing

Three services share one document store and undo history. Hash routes (`src/app/router.ts`)
keep the app working on static hosting:

| Route | Page |
|---|---|
| `#/` | Home: the three services, recent files, samples |
| `#/edit` | The editor workspace (panels, canvas, timeline) |
| `#/customize` | Customize: replace logos/images, brand colors, texts, timing, export |
| `#/optimize` | Optimizer: batch optimization with visual verification |

Without a hash the app opens the editor when a document is open, otherwise home. Keyboard
shortcuts that act on the document only fire on the pages that show it (`src/commands/scope.ts`).

## Loading and workers

- The entry chunk holds the shell, the stores, lottie-web and English strings. The editor
  workspace, the service pages, the JSON editor (CodeMirror), the export dialog, video encoding
  (mediabunny) and other languages load on demand; the workspace is prefetched when idle.
- Heavy work runs in Web Workers: document analysis (issues, statistics, sizes), the optimizer
  and GIF encoding.

## Offline and installation

- Production builds register a service worker (`src/app/pwa.ts`). Its template,
  `src/pwa/service-worker.js`, is written to `sw.js` by `scripts/pwa-plugin.ts` with the list of
  the build's files and a version derived from them.
- Every file is cached when the worker installs. Hashed files are served cache-first; the page
  itself network-first with a short timeout, falling back to the cached copy.
- Updates install in the background and wait; a notice lets the user reload into them, because an
  open page may still load on-demand parts of the version it started with.
- The worker ignores everything outside its scope, and its cache names include the scope, so other
  sites on the same origin are unaffected.
- The web app manifest declares `file_handlers`; files the installed app is opened with arrive
  through the launch queue and go through the same file handlers as dropped files.
- Development builds register no worker. The end-to-end suite blocks workers except in
  `e2e/offline.spec.ts`.

## Data model

- **The Lottie JSON is the source of truth.** The editor never converts it into another
  model, so unknown fields survive a load → edit → export round trip. `src/lottie/types.ts`
  describes the fields the editor understands.
- **The document is immutable** (deep-frozen by immer). All edits go through
  `updateDoc(label, recipe, opts)` from `@/store/document`, which records immer patches for
  undo/redo. Never mutate `getDoc()` results.
- **Continuous gestures are one undo step.** UI controls report a `ChangeGesture`
  (`{ key, final }`); pass `gesture.key` as `coalesceKey` so every update of the drag merges
  into one history entry.
- Large rewrites (JSON editor, optimizer) use `replaceDoc(label, nextDoc)`.
- Nodes are addressed by **JSON paths** (`NodePath`), e.g. `['layers', 3]`,
  `['assets', 1, 'layers', 0, 'shapes', 2]`, `['layers', 0, 'ks', 'p']`. Helpers live in
  `@/lottie/path`. Selection (`nodes`, `keyframes`, `property`) is stored as paths.

## Time

- `usePlayback().frame` is an absolute frame of the root composition (`ip ≤ frame < op`).
- Keyframe `t` values are in the time of the composition that contains the layer
  (lottie-web semantics: `st`/`sr` do not affect a normal layer's keyframes).
- Precomp children: `inner = tm ? tm(outer)·fr : (outer − st) / sr` (`@/lottie/time`).
- Layers are visible while `ip ≤ compFrame < op`.

## Property evaluation and keyframes

- `@/lottie/property`: `isAnimated` (structural — ignores the often-stale `a` flag),
  `evaluateScalar/Vector/Position/Path/TextDocument` (matches lottie-web, incl. spatial
  bezier motion paths, per-dimension easing, hold and legacy `e` keyframes).
- `@/lottie/keyframes`: mutating operations for use inside `updateDoc` recipes
  (`setValueAtFrame` auto-keys animated properties, `insertKeyframe`, `removeKeyframes`,
  `moveKeyframes`, `setSegmentEasing`, `applyEasyEase`, `makeAnimated`, `makeStatic`).
- Easing lives on the **segment**: keyframe *n* holds `o`/`i` for the span n → n+1.

## Rendering

- `LottiePlayer` (`@/player/LottiePlayer`) wraps lottie-web. Rendering is driven by the
  editor (`renderFrame(frame)`); reloads are double-buffered so edits never flash.
- `prepareAnimationData` builds the **render copy**: a JSON deep clone (lottie-web mutates its
  input and throws on frozen objects), normalized for lottie-web's failure modes, with layers
  tagged by path (`le-n_layers_3`) for canvas hit-testing (SVG renderer).
- Expressions are **not** evaluated unless the user opts in (they are `eval`'d JavaScript).

## Themes and slots

- A slottable property carries `sid`; the animation's `slots` holds the default values and
  dotLottie 2 themes (`t/<id>.json`, listed in the manifest) override them per slot
  (`@/lottie/slots`).
- The theme chosen in the Themes section is previewed on the edited canvas only: the player
  shows `previewDocument(doc)`, a themed copy that keeps its identity while nothing changes, so it
  never reloads needlessly. The document itself is not modified.
- Theme edits are undoable; the themes live in the dotLottie container kept with the document and
  are written by the dotLottie export.

## Commands, shortcuts, menus

- Every user action is a command in the registry (`@/commands/registry`): id, title, icon,
  shortcut, `run`, optional `enabled`/`checked`. Menus (`@/app/menus.ts`), the command
  palette and the keyboard handler all read from it.
- Shortcuts match **physical keys** (`KeyboardEvent.code`), so they work with any keyboard
  layout. `mod` = ⌘ on macOS, Ctrl elsewhere.
- Two commands may share a shortcut when their `enabled()` conditions are exclusive
  (e.g. deleting keyframes vs deleting layers).
- Features register commands and dialogs in `src/features/<name>/register.ts`.
- Dialogs: `registerDialog(id, Component)`; open with `openDialog(id, props)`.
- Paste: `registerPasteHandler(handler, priority)`; files (drop, open, paste):
  `registerFileHandler(handler, priority)`.
- Cross-feature UI requests use the event bus (`@/lib/events`): `reveal-code`,
  `reveal-node`, `rename-node`, `zoom-to-node`, `edit-text`.

## Internationalization

- Dictionaries are typed objects: `locales/en/<ns>.ts` is the source of truth and
  `locales/ru/<ns>.ts` must match its shape exactly (checked by TypeScript).
- Components use `const t = useT()` and property access (`t.layers.title`); interpolation
  and plurals are functions in the dictionary (`pluralRu` for Russian forms).
- Non-React code uses `getT()`.

## Design system

The UI follows professional creative tools (Figma, Rive, After Effects): dense, quiet,
neutral chrome so the user's colors read accurately.

- **Tokens only.** Tailwind's default palette is disabled. Use semantic classes:
  `bg-canvas`, `bg-surface-0…3`, `bg-hover`, `bg-pressed`, `bg-selected`, `text-fg`,
  `text-fg-muted`, `text-fg-subtle`, `text-fg-faint`, `border-line`, `border-line-strong`,
  `bg-accent`, `text-accent-text`, `bg-accent-subtle`, `text-danger|warning|success`,
  `bg-label-shape|precomp|text|image|solid|null|other`.
- **Type:** 12px (`text-sm`) for UI text, 11px (`text-xs`) for labels and meta,
  13px (`text-base`) for titles; weights 400/500/600. Numbers use `tabular-nums`.
  Sentence case, no ALL-CAPS labels.
- **Sizes:** controls 24px (`h-6`), toolbar buttons 28px, rows 24–28px, panel headers 32px,
  top bar 40px, status bar 24px. 4px spacing grid. Radii 4–8px (never larger in chrome).
- **Icons:** lucide-react, 14px in rows, 16px in toolbars; icon-only buttons always have a
  tooltip (with the shortcut when there is one).
- **Motion:** 80–150 ms ease-out for hover/press/popovers only; no bounce, no decorative
  animation. Respect `prefers-reduced-motion`.
- **Never:** gradients or glow in chrome, glassmorphism/blur, emoji, extra accent colors,
  big paddings, cards inside cards, toasts for routine actions (only failures, long jobs,
  restores).
- Use the primitives in `@/components/ui` (Button, IconButton, NumberField, ColorField,
  Select, SegmentedControl, Switch, Checkbox, Slider, menus, Dialog, Popover, Tabs,
  PanelHeader, Section, FieldRow, EmptyState, Badge, Tooltip, Kbd, Spinner, toast).

## Testing

- `npm test` runs Vitest. Domain modules in `src/lottie` have unit tests
  (`__tests__/*.test.ts`, Node environment; DOM tests opt into jsdom per file). lottie-web cannot
  be imported in Node. Several tests use `docs/test.json` and `docs/wallet_flag.json` as real-world
  fixtures.
- `npm run e2e` builds the production app and runs the Playwright suite against it (smoke,
  editor, colors, customize, optimizer, export formats, i18n, keyboard and a large-file check).
- `node scripts/screenshot.mjs --url "http://localhost:5173/?sample=bounce" --out shot.png`
  takes a screenshot (`?sample=<id>` and `?url=<file>` load a document on startup). In development
  `window.__le` exposes the stores and actions for scripted checks.
